Run PP1 from `D:\meeting\J26-IT-358` using its fresh Python environment.

In one PowerShell terminal:

```powershell
Set-Location -LiteralPath 'D:\meeting\J26-IT-358'
& '.\.venv\Scripts\python.exe' -I -B '.\scripts\pp1.py' backend
```

In another terminal:

```powershell
Set-Location -LiteralPath 'D:\meeting\J26-IT-358'
& '.\.venv\Scripts\python.exe' -I -B '.\scripts\pp1.py' frontend
```

Open <http://127.0.0.1:3001/crop-planning>. The API is
<http://127.0.0.1:8001>, with health endpoints `/health` and `/ready`.
Stop each foreground service with Ctrl+C. If they are already running, the
launcher refuses to reuse their occupied ports; use the existing PP1 services.
Restart the backend after changing its source. Frontend development reloads this
copy's source changes automatically. Explicit backend restarts avoid unreliable
Windows signal delivery to hidden reload workers.
To stop the background instances started during preparation, run
`powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\stop-pp1.ps1`.
It verifies the recorded PP1 launcher processes before stopping their child
processes, and leaves unrelated services alone. Then use the foreground commands
above to restart.
To start both services hidden in the background, run
`powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-pp1.ps1`.
For backend edits, run the stop helper followed by the start helper.

The operational database is a new, initially empty SQLite file at
`backend/cultivation-concentration/storage/pp1/cultivation_plans.sqlite3`.
Register a new farmer account; original farmer/admin accounts are not copied
into this database. Existing copied database files are preserved separately.
Reference and optional synthetic-demo databases also resolve inside `storage/pp1`.
Research demo inference reads the copied datasets/model artifacts; it does not
train models. The optional operational historical predictor remains unconfigured.

The launcher clears inherited application and connection overrides, selects the
new interpreter, fixes CORS to port 3001, and pins the API to port 8001. It uses
module execution instead of copied Python launchers. `npm run dev` is also pinned
to 127.0.0.1:3001; Next.js embeds only the PP1 API address.

Dependency specification: `backend/cultivation-concentration/requirements.lock.txt`.
The 51 exact locked versions are reinstalled from local wheels after verifying
package files against their installed RECORD hashes. Python entry-point launchers
are regenerated by the fresh environment's pip. Recovery inputs and the
verification manifest are under `scratch/pp1-isolation/`; no old package is
imported or old launcher executed during recovery. To repeat the offline install:

```powershell
& '.\.venv\Scripts\python.exe' -I -B -m pip --isolated install --no-index --no-cache-dir --find-links '.\scratch\pp1-isolation\wheels' -r '.\backend\cultivation-concentration\requirements.lock.txt'
```

The copied Python environment is quarantined at
`scratch/pp1-isolation/copied-venv-DO-NOT-USE`; do not activate or execute it.
Old scratch caches and model metadata retain historical paths as provenance.
The active `.next` and `.next-dev` frontend caches were removed before restart.

PostgreSQL, Redis, Celery and Docker are not needed for the cultivation PP1 app
and are not started. Redis/Celery connection URLs are disabled in PP1 runtime.
The optional Compose configuration has its own `j26_pp1` project, container names,
explicit volume names and loopback ports 55433 (PostgreSQL) and 56380 (Redis).
These reserved settings have not been used to connect to any database. Other
backend components are outside this startup configuration.

To reapply additive migrations to this PP1 database only:

```powershell
& '.\.venv\Scripts\python.exe' -I -B '.\scripts\pp1.py' init-db
```

Local preparation logs, integrity fingerprints and check results are under
`scratch/pp1-isolation/`. Configuration backups there contain the old connection
settings for reference only; do not restore them for PP1 use. Model and dataset
files are preserved. No retraining is part of setup.
